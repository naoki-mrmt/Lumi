# 04. UI Design — 画面設計とデザインシステム

## 1. デザイン哲学

**「沈黙のスカウティングツール」**

派手な装飾を排し、データそのものを主役にする。プロアナリストが2階席で、薄暗い体育館で、長時間使い続けても疲れない・ノイズがない・即座に読める道具を目指す。

### 参照するデザイン言語
- **Linear**：ダーク優先、控えめなアクセント、高密度情報を整然と配置
- **Apple Sports app**：スポーツデータの読みやすさ、数値主役の組版
- **Things 3 / Mela**：SwiftUIネイティブのApple品質

## 2. デザイン原則（5箇条）

迷ったらこれに立ち返る：

1. **データが主役。装飾は脇役。**
   - スコア・数値・選手番号を最大の主張にする
   
2. **ダークモードがデフォルト。**
   - 体育館は薄暗い。明るい画面は目に痛い。バッテリーも食う。
   - ライトモード対応は実装するが推奨はダーク。
   
3. **等幅数字（Tabular Numbers）を徹底する。**
   - スタッツが揃う。プロらしさが一気に出る。
   
4. **アニメーションは情報伝達のためだけに使う。**
   - 装飾的なバウンス・パーティクルは禁止
   - 状態変化（決定・ミス・リアルタイム同期）の通知のみOK
   
5. **ワンタップで戻れる、ワンタップで取り消せる。**
   - 「壊れない安心感」がエレガンス

## 3. カラーパレット

### 3.1 ベースカラー（ダーク優先）

| 用途 | カラー | 値 |
|---|---|---|
| 背景（最暗） | Background | `#0A0A0B` |
| サーフェス（カード等） | Surface | `#16161A` |
| サーフェス（強調） | SurfaceElevated | `#1F1F24` |
| 枠線 | Border | `#2A2A30` |
| 文字（主） | TextPrimary | `#F5F5F7` |
| 文字（副） | TextSecondary | `#8E8E93` |
| 文字（無効） | TextTertiary | `#48484A` |

### 3.2 アクセント・状態カラー

| 用途 | カラー | 値 | 用途 |
|---|---|---|---|
| アクセント | AccentBlue | `#0A84FF` | プライマリ・選択中 |
| 決定 | EvalExcellent | `#30D158` | ◎・成功・好プレー |
| 良 | EvalGood | `#64D2FF` | ○・及第点 |
| 普通 | EvalNormal | `#FFD60A` | △・継続中 |
| ミス | EvalError | `#FF453A` | ×・失点 |
| 警告 | Warning | `#FF9F0A` | バッテリー残少等 |

### 3.3 信号機メタファー

評価4段階は **緑 → 水色 → 黄 → 赤** の信号機/温度的な配色。直感で押せる。

## 4. タイポグラフィ

### 4.1 フォントスタック

| 用途 | フォント | サイズ |
|---|---|---|
| スコア（試合状態の主役） | SF Pro Rounded Bold | 56pt〜72pt |
| 大見出し | SF Pro Display Semibold | 32pt |
| セクション見出し | SF Pro Display Medium | 22pt |
| 本文・操作テキスト | SF Pro Text Regular | 17pt |
| キャプション・ラベル | SF Pro Text Regular | 13pt |
| スタッツ数値（KPI） | SF Pro Rounded with `.monospacedDigit()` | 24pt〜36pt |
| 表のセル数値 | SF Mono | 15pt |

### 4.2 数字の組版ルール

すべての**スタッツ表示で `.monospacedDigit()` を必須**にする。これにより列の数字がきれいに揃い、Data Volley的なプロフェッショナル感が出る。

```swift
Text("38.2%")
  .font(.system(.title, design: .rounded).monospacedDigit())
```

## 5. レイアウト原則

### 5.1 8の倍数グリッド
- 余白・サイズはすべて8の倍数（8, 16, 24, 32, 48, 64...）
- 例外：1px のヘアライン枠は許可

### 5.2 高密度 vs 余白のバランス
- 入力画面：高密度（情報量重視・ベンチで一目把握）
- 振り返り画面：適度な余白（読みやすさ重視）
- セットアップ画面：たっぷり余白（落ち着いて操作）

## 7. インタラクション仕様

### 7.1 触覚フィードバック（Haptic Feedback）

評価ごとに違う重さに：

| 操作 | フィードバック |
|---|---|
| ◎ 決定 | `success` ハプティック（重め） |
| ○ 良 | `light` impact |
| △ 普通 | `selection` |
| × ミス | `warning` ハプティック |
| アンドゥ | `medium` impact |
| 試合終了 | `success` + 軽いアニメーション |

iOS 26 の `SensoryFeedback` API を使用。

### 7.2 アニメーション

- 画面遷移：`matchedGeometryEffect` で滑らかに
- KPI更新：数値が変わる時に `contentTransition(.numericText())` で自然にフェード
- リアルタイム同期：受信時に微小なフラッシュ（500ms）

### 7.3 ジェスチャー

| ジェスチャー | 機能 |
|---|---|
| シングルタップ | 選択・決定 |
| ロングプレス | 詳細メニュー（プレーカードを長押し→詳細記録） |
| 左スワイプ | アンドゥ（直前プレー） |
| 右スワイプ | やり直し（リドゥ） |
| ピンチ | コート図のズーム（着地点詳細時） |

## 8. アクセシビリティ

- VoiceOver対応：最低限すべての操作要素にラベル付与
- Dynamic Type対応：本文要素は `Font.body` 等のシステムフォントを使用
- カラーコントラスト：WCAG AAレベル（4.5:1以上）を遵守
- 色だけに依存しない：評価4段階は色 + アイコン（◎○△×）

## 9. iOS 26 の Liquid Glass 活用

- 入力画面の評価ボタン：Glass マテリアルで奥行き感
- KPI カード：Frosted glass background
- ナビゲーションバー：自動的に Liquid Glass 適用

### 10.2 デザイン要件
- 白背景・黒文字（紙印刷想定）
- フォントは本アプリと同じSF Pro系
- 数値は等幅で揃える
- アクセントカラーはグレー系のみ（カラー印刷でも見やすく）

## 11. 実装上の注意

### 11.1 SwiftUIで Tabular Numbers を使う

```swift
extension Font {
  static var statValue: Font {
    .system(.title2, design: .rounded)
      .monospacedDigit()
      .weight(.semibold)
  }
}
```

### 11.2 カラー定義は Asset Catalog

`.xcassets` の Color Set でダーク/ライト両対応で管理。

### 11.3 SwiftUI Preview で常にダーク確認

```swift
#Preview {
  MyView()
    .preferredColorScheme(.dark)
}
```

主要画面のスナップショットテストもダーク/ライト両方で生成。
