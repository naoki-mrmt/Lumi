# 01. Product Requirements Document (PRD)

## 0. プロダクト名

**Lumi**（リュミ）

- App Store 副題：**Lumi — Volleyball Scouting**
- Bundle Identifier：`com.muramoto-co.lumi`
- 由来：フランス語の lumière（光）に由来。データに光を当て、試合の本質を映し出すという意図。Apple品質のエレガントな短いプロダクト名として選定。

## 1. プロダクトビジョン

**「9人制バレーボールの戦術と振り返りを変える、最も使いやすいスカウティングアプリ」**

データバレー4のような業務ソフト的な複雑さを脱却し、Apple品質のエレガントなUIで、アナリスト/監督/コーチ/選手の誰もが直感的に使える9人制特化のスカウティング体験を提供する。

## 2. 解決したい課題

### 2.1 既存ソリューションの問題点

| ツール | 問題 |
|---|---|
| **Data Volley 4 Pro** | 年14万円、Windows専用、6人制前提、習得コスト高い |
| **Data Volley 4 Lite** | 上記の廉価版だが依然として6人制前提 |
| **Click & Scout** | iPad対応だが Data Volley 系列の簡易版、9人制最適化なし |
| **VolleyPlus** | 月額1,500〜9,800円、6人制ベース |
| **紙の記録** | 集計・共有ができない、リアルタイム性なし |

### 2.2 9人制特有の未解決課題

- ローテーションがない → 6人制の「ローテ別分析」が機能しない
- サービス順管理が独自 → 適切なツールが存在しない
- フォーメーション多様（5-1-3 / 6-3 / 4-2-3 等）→ 集計軸が不足
- 2回サーブ制 → サーブ統計の取り方が違う
- ブロックも接触1回 → ラリー記録ロジックが違う
- 21点3セットマッチ → 試合進行管理が違う

## 3. ユーザーペルソナ

### 3.1 Primary: 実業団チームのアナリスト

- 30〜40代、男女問わず
- 元バレーボール選手 or 競技経験者
- 試合中は2階席や俯瞰位置で iPad を操作
- データバレーの操作経験あり（学習意欲は高い）
- ベンチに数値を渡し、試合後の分析資料も作る
- **求めるもの**：高速入力・正確な集計・ベンチへの即時共有・PDFレポート

### 3.2 Secondary: 監督・コーチ

- 40〜60代、競技経験豊富
- iPhoneやiPadは普段使いするが業務ソフトには慣れていない
- 試合中はベンチで指示を出す、選手交代やタイムアウト判断をする
- **求めるもの**：パッと見て分かる数値・選手の状態・直感的なUI

### 3.3 Secondary: ママさんバレー指導者

- 40〜60代、女性主体のチーム
- ITリテラシーは様々、iPad 操作は基本のみ
- アナリスト不在で監督自身が記録するケース多数
- **求めるもの**：低コスト・シンプル操作・基本的な集計が出せれば十分

### 3.4 Tertiary（Phase 2）: 選手

- 自分のプレーを振り返りたい
- 動画と数値を紐付けて見たい
- iPhone で個人的に確認

## 4. ユースケース

### 4.1 試合前のセットアップ

| ステップ | 操作 | 目標時間 |
|---|---|---|
| アプリ起動・ログイン | （既ログインなら省略） | 即時 |
| 新規試合作成 | 対戦相手・大会名・日時・試合タイプ・会場 | 30秒 |
| スタメン9人選択 | 選手マスタから選択（前回コピー可） | 15秒 |
| サービス順設定 | ドラッグで並び替え | 15秒 |
| フォーメーション選択 | 5-1-3 / 6-3 等 | 5秒 |
| 相手スタメン背番号 | 任意・スキップ可 | 30秒 |
| 試合コード発行・共有 | ベンチ端末に共有 | 10秒 |
| **合計（2回目以降）** | | **2分以内** |

### 4.2 試合中のリアルタイム入力

- アナリストが2階席で iPad に入力
- 1ラリーで2〜10タップ（モード次第）
- リアルタイムで KPI が計算され、ベンチ iPad に同期
- 監督がベンチ iPad で状況確認・選手交代判断

### 4.3 試合中の選手交代

- Recorder が「交代」モードを開く
- 入る選手・出る選手を選択
- サービス順を自動引き継ぎ
- 選手交代カウンタが自動加算（4回/セット制限を表示）

### 4.4 タイムアウト

- Recorder が「TO」ボタンタップ
- 自/相手を選択 → スコア自動取得 → 確定
- 1セット2回上限を超えそうになるとアラート

### 4.5 セット間

- 「セット間ビュー」が自動表示
- 中間集計 KPI を確認
- 次セットのフォーメーション設定
- 次セットのサービス順は自動引き継ぎ（前セット最終サーバーの次）

### 4.6 試合終了後の振り返り

- 試合データから自動でサマリ生成
- 主要 KPI、選手別スタッツ、得点推移グラフ、連続得点ハイライト
- PDFサマリ出力 → 共有シートで監督・コーチに配布
- CSV エクスポートでさらなる分析（実業団アナリスト向け）

### 4.7 動画後付け同期（試合終了後）

- 別撮りした動画ファイルをアプリにアップロード
- 試合開始時刻を1点合わせる
- 各プレーのタイムスタンプから自動でシーン抽出
- 「あのアタック決定の瞬間」がワンタップで再生可能

## 5. プロダクト目標（Goals）

### 5.1 Phase 1.0 MVP の成功基準

- ✅ 9人制の試合を、ルール準拠で正確に記録できる
- ✅ 1ラリーの入力が10秒以内（スタンダードモード）
- ✅ Recorder iPad の入力が2秒以内に Viewer iPad に反映
- ✅ オフラインで完全に試合進行可能、復帰時に自動同期
- ✅ 試合サマリ PDF が試合終了から1分以内に生成可能
- ✅ 自チームの最低3試合を、本アプリだけで完遂

### 5.2 数値目標（KPI）

| 指標 | 目標 |
|---|---|
| セットアップ時間（2回目以降） | 2分以内 |
| 1ラリー入力時間（スタンダード） | 10秒以内 |
| 1ラリー入力時間（クイック） | 5秒以内 |
| Recorder→Viewer 同期レイテンシ | 2秒以内（オンライン時） |
| クラッシュ率 | 0.1%未満 |
| ロジック層テストカバレッジ | 90%以上 |
| TCA Reducer テストカバレッジ | 80%以上 |

## 6. 非ゴール（Non-Goals）

明示的に**やらないこと**：

- ❌ 6人制対応（Phase 2以降でも基本やらない）
- ❌ 自動ビデオ解析・AIによるプレー判定
- ❌ ローカルルール対応（3点連続交代等）
- ❌ Phase 1での iPhone 対応
- ❌ Phase 1でのアタッカー打点高さ等の高度メトリクス
- ❌ Phase 1での対戦相手データベース・横断分析
- ❌ Windows / Android 対応

## 7. 制約とリスク

### 7.1 制約

- **個人開発・CC主導**：開発リソースは限定的、スコープ管理が重要
- **オフライン要件**：体育館のネット環境が不安定でも試合完遂できる必要
- **9人制ニッチ**：市場規模は小さい、技術選定はビジネス判断より「作りやすさ」を優先

### 7.2 主要リスク

| リスク | 影響 | 緩和策 |
|---|---|---|
| 試合中のクラッシュでデータロス | 致命的 | クラッシュリカバリ機構を初期から作り込み（M7） |
| 体育館でネット切断 | 大 | オフライン継続・自動同期（M4） |
| 入力速度が間に合わない | 大 | 3モード設計・実戦テストで検証（M2/Phase 1.4） |
| 統計定義の混乱（決定率vs効果率） | 中 | Data Volley準拠を明文化（03_DOMAIN_MODEL） |
| Supabase Free tier超過 | 小 | 自チーム規模ならまず超えない |
