## 2. Phase 1.0：MVP（実戦投入レベル）

**目標**：自チームの試合を本アプリだけで完遂できる状態

**期間**：9〜12週間（約3ヶ月）

**マイルストーン構成**：

| ID | 名前 | 期間 | 概要 |
|---|---|---|---|
| **M0** | プロジェクト基盤 | 1週 | SPM構成・TCA・Supabase初期化 |
| **M1** | チーム・試合・サービス順 | 2週 | データモデル・サービス順自動算出 |
| **M2** | 入力UI コア | 2-3週 | 3モード入力UI・コートタップ・タイムライン |
| **M3** | KPI計算・リアルタイム表示 | 2週 | スタッツエンジン・連続得点ハイライト・ベンチ画面 |
| **M4** | 同期・認証 | 2週 | Supabase Realtime・チームコード・Sign in with Apple |
| **M5** | 振り返り・PDF/CSV出力 | 1-2週 | 試合後画面・PDF生成・共有 |
| **M6** | 動画後付け同期 | 1-2週 | 動画アップロード・タイムスタンプ紐付け |
| **M7** | エラーハンドリング・障害時UX | 並行 | 各マイルストーン内+統合 |
| **M8** | 観測性・クラッシュレポート | 並行 | Sentry・OSLog統合 |

各マイルストーン詳細は `docs/tasks/Mx_*.md` 参照。

### 2.1 Phase 1.0 完了の定義（DoD）

- ✅ 9人制の試合を、ルール準拠で正確に記録できる
- ✅ 1ラリー入力10秒以内（スタンダードモード）
- ✅ Recorder→Viewer 同期2秒以内
- ✅ オフライン完全対応・復帰時自動同期
- ✅ 試合サマリPDF生成可能
- ✅ 自チーム最低3試合を本アプリで完遂
- ✅ ロジック層テストカバレッジ90%以上
- ✅ クラッシュ率0.1%未満（実戦テスト時）
- ✅ TestFlight 配布可能な状態

## 10. リスク・依存関係

### 10.1 マイルストーン間の依存

```
M0 → M1 → M2 → M3 → M5
              ↓
              M4 → M6
              ↓
              M7, M8（並行・横断）
```

### 10.2 主なリスク

| リスク | 影響 | 緩和策 |
|---|---|---|
| 入力UIの使い勝手が想定より悪い | M2の手戻り | 早期にプロトタイプ作成・実機確認 |
| Supabase Realtime のレイテンシ問題 | M4の遅延 | 早期にPoC・必要なら同期方式変更検討 |
| 動画同期の精度問題 | M6の遅延 | シンプルな手動同期から始める |
| 実戦テストでの致命的バグ発見 | Phase 1.5延長 | M7で予め障害ケースを潰しておく |

## 11. リリース戦略

### 11.1 Phase 1.0 → 1.1 → 1.5

- **TestFlight内部テストのみ**（自分・チームメンバーのみ）
- 本番Supabaseは個人プロジェクト
- データバックアップは適宜手動でも可

### 11.2 Phase 2.0 〜 2.3

- TestFlight外部テストへ拡張（友人・ベータユーザー）
- フィードバック収集・改善

### 11.3 Phase 2.4

- App Store公開
- 課金導入の場合：StoreKit 2 で実装
- マーケティング戦略は別途検討
